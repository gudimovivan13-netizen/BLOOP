# BLOOP — соцсеть и мессенджер

BLOOP — веб-соцсеть в духе ВКонтакте: лента с постами, клипы с вертикальной
лентой как в TikTok, раздел длинных видео, профили с аватарами — плюс
встроенный мессенджер с личными и групповыми чатами в реальном времени.
Всё в одном репозитории и с минимумом зависимостей: `express`, `socket.io`
и `multer` (загрузка файлов); база — встроенный в Node.js SQLite (`node:sqlite`),
пароли — `scrypt`, сессии — подписанные HMAC-токены.

## Возможности

**v4.4 — модель на энциклопедии, книгах и коде**
- 📚 **Корпус ×3.7** (28.7 МБ): диалоги (35 345 блоков ×2) + **2700 научных
  статей по ~100 наукам** Википедии + **25 книг Викитеки** от «Слова о полку
  Игореве» до Бунина + **25 файлов реального кода проекта**. BPE: 5342
  токена, 5.27 млн токенов корпуса, 0% unk
- 🧠 **Переобучена**: 7400 шагов в два косинус-цикла, val_loss 4.27
- 🔎 **Слой знаний**: 14 000 фрагментов корпуса, IDF-поиск с бонусом за
  заголовок и русско-английскими синонимами (функция → function).
  «что такое фотосинтез», «кто такой Пушкин», «напиши функцию сортировки» —
  отвечают настоящими фрагментами статей/книг/кода с указанием источника;
  болтовня — за трансформером и классификатором
- 📵 Ноль внешних API — индекс и веса локальны везде

**v4.3 — настоящая языковая модель + звонки**
- 🤖 **GPT-трансформер обучается прямо в репозитории**: `scripts/llm/` —
  сбор корпуса диалогов (OpenSubtitles/OPUS, стримом), BPE-токенизатор
  (~4.7k словарь), обучение декодер-трансформера на numpy с ручным
  обратным распространением (проверено численной градиентной проверкой,
  ошибка < 1e-6). ~1 млн параметров, 2 слоя, контекст 128 токенов.
  Инференс — на чистом JS (`src/ai/llm.js`, KV-кэш, top-k сэмплинг):
  сервер, exe и APK отвечают настоящей нейросетью, без внешних API
- ☎️ **Звонки работают**: в личном чате появились кнопки аудио ☎️ и
  видео 📹 звонка; полноэкранный оверлей входящего звонка с пульсацией

  пост-обрабатываются (капитализация), при слабой генерации включается
  классификатор намерений

**v4.2 — BLOOP AI: своя нейросеть без внешних API**
- 🧠 **Настоящая нейросеть внутри**: классификатор намерений — многослойный
  перцептрон (MLP с обратным распространением ошибки), обучается при старте

- 🔥 **Вирусометр BLOOP AI**: оценка текста 0–100 до публикации + советы

- 📵 **Ноль внешних API**: всё считается внутри BLOOP — на сервере (Node),

## BLOOP AI — встроенная нейросеть (без внешних API)

Ассистент в окне «BLOOP AI» — не обёртка над чужим API, а своя нейросеть.
Код живёт в `src/ai/` и одинаково работает в Node и в браузере:

- `src/ai/text.js` — нормализация русского текста, стемминг и хэш-признаки:
  слова, биграммы соседних слов и символьные триграммы (разреженный вектор
  ~3.5k слотов);
- `src/ai/net.js` — MLP «вход → скрытый слой (48 нейронов, ReLU) → softmax»
  с обучением методом обратного распространения ошибки (SGD, seeded —
  обучение детерминировано);
- `src/ai/data.js` — обучающие фразы (13 намерений: приветствия, идеи постов,
  подписи, хэштеги, клипы, Вирусометр, стиль, помощь по поиску/звонкам/ботам/
  группам…) и пулы ответов;
- `src/ai/engine.js` — сборка: обучение, классификация + гибридный слой
  ключевых слов, генераторы (идеи, теги, Марковская цепь «в моём стиле»,
  Вирусометр 0–100) и память диалога («ещё» повторяет последний тип идеи).

Модель обучается при каждом старте сервера (~0.3 с) — добавили фразы
в `data.js` — при следующем запуске сеть уже знает их. Данные для ответов
берутся из самой соцсети: последние посты пользователя, его теги и тренды
BLOOP передаются в генераторы как контекст.

### Языковая модель (v4.3)

Сверх классификатора в BLOOP встроена настоящая языковая модель — GPT-трансформер,
обученный на реальных диалогах:

```
scripts/llm/corpus.py   # корпус: стрим OpenSubtitles (OPUS) → 33k диалогов
scripts/llm/corpus_science.py # Википедия (~100 наук), Викитека (книги), код
scripts/llm/build_index.py    # индекс знаний: 14k фрагментов → bloop-knowledge.json
scripts/llm/bpe.py            # BPE-токенизатор (5342 токена, 0% <unk>)
scripts/llm/gpt_train.py# обучение: numpy, ручной backprop, Adam, cosine LR
scripts/llm/export.py   # экспорт весов (fp16 → base64) в public/vendor/bloop-llm.json
```

Запуск обучения: `python3 scripts/llm/gpt_train.py --gradcheck` (проверка
градиентов), затем `--steps 3200` (~19 минут на CPU). Веса коммитятся в
репозиторий, инференс — `src/ai/llm.js`: KV-кэш, temperature/top-k сэмплинг,
штраф повторов. Ассистент сначала пробует LLM, при слабой генерации —
классификатор намерений из `src/ai/engine.js`.

Интеграция: сервер (`/api/assistant`, контекст из SQLite), APK
(`local-server.js` вызывает `window.BLOOP_AI` из `public/vendor/bloop-ai.js`
— тот же бандл, собранный esbuild'ом, работает офлайн на устройстве) и exe
(движок внутри встроенного сервера). Ни один байт не уходит наружу — внешних
API нет вообще.

## Windows — приложение со своим окном

Готовый exe лежит в папке [releases/](releases/) — `BLOOP-4.1.exe` рядом
с APK и суммами SHA256. С версии 4.1 это настоящее десктоп-приложение
(обёртка Electron из `app/desktop/`): двойной клик открывает окно BLOOP
с иконкой в панели задач — без консоли и без вкладки браузера.

1. Положите exe в любую папку и запустите двойным кликом — откроется окно
   приложения; данные (база, загрузки) лежат в `data` рядом с exe, и если
   раньше пользовались exe 4.0 — база подхватится автоматически.
2. Порт выбирается сам: 3000, если свободен, иначе любой свободный.
3. Повторный запуск поднимает уже открытое окно, а не второй экземпляр.

Файл не подписан сертификатом: SmartScreen покажет предупреждение —
«Подробнее → Выполнить в любом случае» (это нормально для личных сборок).
Пересборка: `bash scripts/build_exe.sh` (esbuild-бандл сервера +
electron-builder portable; детали в `app/desktop/`).

## Android APK — автономный режим без сервера

Готовый APK последней версии лежит рядом с exe в папке
[releases/](releases/) — `BLOOP-4.2.apk` (versionCode 12) с нейросетью
офлайн внутри.

BLOOP собирается в Android-приложение (Capacitor). В APK работает
**локальный режим**: весь «сервер» — виртуальный, прямо на устройстве
(`public/local-server.js`): все REST-маршруты на `localStorage`,
медиа — в `IndexedDB`, realtime-события — через локальную шину.
Приложение запускается и полноценно работает без `npm start` и без сети:
регистрация/вход, лента, клипы, видео, чаты, лайки, комментарии,
уведомления, хэштеги, Нейро (в офлайн-режиме — честными заготовками
вместо нейросети), темы.

Особенность локального режима: данные хранятся на устройстве, поэтому это
«своя копия BLOOP» — синхронизации между разными телефонами нет. Серверная
веб-версия с общей базой остаётся без изменений (`config.js: mode 'server'`).

### Установка

1. Взять `BLOOP.apk` (подписанный release, v3.3+) и открыть на телефоне.
2. Разрешить установку «из этого источника» (Настройки → Безопасность
   → Установка неизвестных приложений → разрешить для браузера/проводника).
3. Приложение «BLOOP» появится в меню; при первом запуске — регистрация.

**Если пишет «Приложение не установлено»:**

- **Раньше ставился старый BLOOP (v3.1–3.2)?** Удалите его (иконка →
  Удалить) и ставьте новый один раз. Начиная с v3.3 все сборки подписаны
  постоянным ключом (`app/android/app/bloop-release.keystore`), поэтому
  следующие обновления будут ставиться поверх без удаления.
- **Скачивали APK заново?** Частично скачанный файл не ставится —
  удалите и скачайте снова.
- **Android 5.0 и старше?** Минимальная версия — Android 5.1 (minSdk 22).
- **Проверьте файл**: `apksigner verify BLOOP.apk` — подпись
  `CN=BLOOP, O=BLOOP, C=RU`.

## Доставка кода входа (почта / SMTP)

Код подтверждения отправляется **настоящим письмом на указанную почту**
через SMTP (`src/email.js`, nodemailer). Подходит любой почтовый ящик с
доступом к SMTP: Gmail, Яндекс, Mail.ru, свой домен.

1. Получите «пароль приложения» для SMTP:
   - **Gmail**: включите двухфакторку → пароли приложений (app password);
   - **Яндекс**: Настройки → Почтовые программы → пароль приложения;
   - **Mail.ru**: Безопасность → пароль для внешних приложений.
2. Запустите сервер:
   ```bash
   BLOOP_SMTP_HOST=smtp.gmail.com \
   BLOOP_SMTP_PORT=465 \
   BLOOP_SMTP_USER=user@gmail.com \
   BLOOP_SMTP_PASS=пароль-приложения \
   BLOOP_SMTP_FROM="BLOOP <user@gmail.com>" \
   npm start
   ```
3. При входе по почте на адрес уйдёт фирменное письмо с кодом (действует
   5 минут, 5 попыток, не больше 1 письма в 30 секунд на адрес).

Без SMTP-конфигурации код печатается в консоль сервера — удобно на этапе
разработки; `BLOOP_EMAIL_DEBUG=1` дополнительно возвращает код в
API-ответе. Если SMTP временно недоступен, код тоже уходит в лог как
fallback — регистрация не блокируется.

В офлайн-приложении (APK без сервера) сети нет — код показывается сразу
тостом «Почта BLOOP».

## Боты и мини-аппы (v6)

В BLOOP встроена собственная платформа ботов — как в Telegram, но целиком своя,
без внешних API. Бот — специальный пользователь: у него есть чаты, он получает
сообщения и отвечает через код, исполняемый в изолированной песочнице.

### Создание бота

Профиль → «Мои боты» → «Создать бота». Новый бот сразу работает: внутри
шаблон «Эхо-бот». Код редактируется во вкладке «Код» (шаблоны: эхо, команды
с клавиатурой, счётчик на состоянии, викторина), логи `console.log` — там же.

### Контракт кода бота (объект `ctx`)

| Свойство | Описание |
| --- | --- |
| `ctx.event` | `start` (первый чат) \| `message` \| `callback` (кнопка) \| `miniapp` |
| `ctx.message` | `{ text, command, args, argsText, message_id }` — для сообщений |
| `ctx.callback` | `{ data, message_id }` — нажатие инлайн-кнопки |
| `ctx.miniapp` | `{ data }` — событие из мини-аппа бота |
| `ctx.reply(text, { keyboard })` | ответ в чат; `keyboard` — ряды кнопок |
| `ctx.state.get(k, def)` / `.set(k, v)` | постоянное состояние бота (JSON, ≤100 ключей) |
| `ctx.user` | `{ id, name, username }` отправителя |
| `console.log(...)` | попадает в логи редактора |

Клавиатура — массив рядов, кнопка — `{ t: 'Надпись', d: 'данные' }` или просто
строка: `ctx.reply('Меню:', { keyboard: [[{ t: 'Пинг', d: 'ping' }], [{ t: 'О боте', d: 'about' }]] })`.
Ограничения: таймаут исполнения 3 с, код ≤ 20 000 символов, без `require`,
сети и таймеров — только чистый JS + `ctx`.

### Мини-аппы

Бот может нести мини-апп — HTML-страницу, открывающуюся внутри BLOOP
(кнопка «Мини-апп» в чате с ботом). Код задаётся во вкладке «Мини-апп»;
внутри доступен SDK `window.BMA`:

- `BMA.ready(cb)` — пользователь (`BMA.user`), состояние бота (`BMA.state`);
- `BMA.sendData(data)` — событие боту (`ctx.event === 'miniapp'`), в ответ — свежий `state`;
- `BMA.setMainButton(text, cb)` / `BMA.hideMainButton()` / `BMA.close()`.

Страница раздаётся на `/miniapp/<юзернейм>`; в офлайн-режиме — через blob-URL.
SDK: `/miniapp-sdk.js` подключается автоматически.

### Каталог

Раздел «Боты» при создании чата (вкладка рядом с «Люди») показывает включённые
боты. Кнопка в шапке профиля «Мои боты» — управление своими.

### Bot HTTP API (по токену бота)

```
Authorization: Bearer bta_...

GET /api/botapi/getMe                      — карточка бота
POST /api/botapi/sendMessage               — { chat_id, text, keyboard? }
GET  /api/botapi/getUpdates?timeout=25000  — long polling очереди событий
```

Событие очереди: `{ type: 'message'|'callback'|'miniapp', chat_id, text?, data?,
message_id?, from: { id, name, username }, seq, ts }`.

### Хранение

Таблицы `bots` (код, токен, счётчики, мини-апп) и `bot_states` (состояние).
Сообщения ботов хранятся как обычные сообщения чата с колонкой `kb`
(инлайн-клавиатура). В офлайн-режиме всё то же самое работает локально
(движок в `public/local-server.js`, данные в localStorage).
