# BLOOP — соцсеть и мессенджер

BLOOP — веб-соцсеть в духе ВКонтакте: лента с постами, клипы с вертикальной
лентой как в TikTok, раздел длинных видео, профили с аватарами — плюс
встроенный мессенджер с личными и групповыми чатами в реальном времени.
Всё в одном репозитории и с минимумом зависимостей: `express`, `socket.io`
и `multer` (загрузка файлов); база — встроенный в Node.js SQLite (`node:sqlite`),
пароли — `scrypt`, сессии — подписанные HMAC-токены.

## Возможности

**v4 — телефон, голос, рилсы из камеры и Вирусометр**
- 📱 **Вход по номеру телефона с 6-значным кодом** — код генерируется
  сервером (HMAC-хэш в БД, 5 минут, 5 попыток, антиспам «1 код в 30
  секунд»). Доставка — **настоящая SMS на указанный номер** через
  переключаемый слой `src/sms.js`: SMS.ru / SMSC.ru / Twilio / свой
  webhook (см. «Доставка кода входа»); без настроенного шлюза код
  печатается в консоль сервера; в офлайн-приложении — тост «SMS от
  BLOOP». Аккаунт создаётся автоматически, повторный вход — без дубликатов
- 🎤 **Голосовые сообщения в чатах**: запись MediaRecorder прямо в чате
  (WebM/Opus, fallback MP4/OGG), плеер с волной и прогрессом,
  длительность; хранение как медиа в чате и ленте чата («🎤 Голосовое»)
- 🎬 **Съёмка рилсов прямо в приложении**: в композере клипа/видео кнопка
  «Снять рилс» — фронтальная/тыловая камера, запись до 60 секунд с
  таймером, превью, затем описание и публикация в обычном порядке
- 🔥 **Вирусометр Floop** — уникальная фишка: до публикации оценивает пост
  на 0–100 (длина, вопрос, хэштеги, медиа, эмодзи, капс, время суток) и
  даёт конкретные советы; после публикации у постов появляется «пульс» —
  🔥 Горит / 📈 Набирает обороты / 🌱 Растёт (динамика лайков+комментариев
  в первые 48 часов)
- 🤖 **Floop** (бывший Нейро) — помощник с фирменной аватаркой; офлайн-режим
  подсказывает идеи, подписи, хэштеги, объясняет Вирусометр
- 🎨 Кастомные аватарки-бейджи разделов (Лента, Клипы, Видео, Чаты) и PWA:
  BLOOP ставится на главный экран iPhone/Android как приложение
  (manifest.webmanifest + иконки)

**Соцсеть v3 — живая и умная**
- Живая лента: новые посты, лайки и комментарии появляются у всех
  пользователей мгновенно, без перезагрузки страницы (Socket.IO)
- Уведомления: колокольчик с бейджем, тосты в реальном времени,
  «прочитать всё»; уведомляем о лайках и комментариях к вашим публикациям
- 🤖 **Нейропомощник** в профиле: чат с настоящей нейросетью —
  придумывает идеи постов, подписи к фото и клипам, хэштеги, отвечает на
  вопросы (с сохранением истории диалога; без подключённого SDK честно
  работает в офлайн-режиме)
- Хэштеги и тренды: #теги в постах кликабельны, боковая панель показывает
  тренды недели и «кто онлайн»
- Поиск по постам прямо из ленты, фид по хэштегу
- Статистика профиля: лайки и просмотры всех публикаций
- Светлая и тёмная темы (кнопка в меню и на профиле, запоминается)

**Соцсеть v2**
- Лента постов: текст + изображение, лайки, комментарии, счётчик просмотров
- Клипы: вертикальная лента с автоплеем по скроллу (scroll-snap), лайк,
  комментарии, звук по тапу, загрузка видео до 300 МБ
- Видео: сетка карточек с длительностью, плеер в модальном окне
- Профили: аватар, имя, «о себе», счётчики, вкладки с контентом
- Свои публикации можно удалять (кнопка корзины на карточке)

**Мессенджер (v1)**
- Личные чаты 1-на-1 и групповые (создание с выбором участников)
- Мгновенная доставка по WebSocket, автопереподключение
- Онлайн-статусы, индикатор «печатает…», счётчик непрочитанных (и в заголовке)
- Изображения в чатах до 8 МБ (PNG/JPEG/GIF/WebP)

**Общее**
- Адаптивный интерфейс: телефон (нижняя навигация), планшет, десктоп
- Аватары-картинки у пользователей, тосты, модалки

## Android APK — автономный режим без сервера

BLOOP собирается в Android-приложение (Capacitor). В APK работает
**локальный режим**: весь «сервер» — виртуальный, прямо на устройстве
(`public/local-server.js`): все REST-маршруты на `localStorage`,
медиа — в `IndexedDB`, realtime-события — через локальную шину.
Приложение запускается и полноценно работает без `npm start` и без сети:
регистрация/вход, лента, клипы, видео, чаты, лайки, комментарии,
уведомления, хэштеги, Нейро (в офлайн-режиме — честными заготовками
вместо нейросети), темы.

Особенность локального режима: данные хранятся на устройстве, поэтому это
«своя копия BLOOP» — синхронизации между разными телефонами нет. Серверная
веб-версия с общей базой остаётся без изменений (`config.js: mode 'server'`).

### Установка

1. Взять `BLOOP.apk` (подписанный release, v3.3+) и открыть на телефоне.
2. Разрешить установку «из этого источника» (Настройки → Безопасность
   → Установка неизвестных приложений → разрешить для браузера/проводника).
3. Приложение «BLOOP» появится в меню; при первом запуске — регистрация.

**Если пишет «Приложение не установлено»:**

- **Раньше ставился старый BLOOP (v3.1–3.2)?** Удалите его (иконка →
  Удалить) и ставьте новый один раз. Начиная с v3.3 все сборки подписаны
  постоянным ключом (`app/android/app/bloop-release.keystore`), поэтому
  следующие обновления будут ставиться поверх без удаления.
- **Скачивали APK заново?** Частично скачанный файл не ставится —
  удалите и скачайте снова.
- **Android 5.0 и старше?** Минимальная версия — Android 5.1 (minSdk 22).
- **Проверьте файл**: `apksigner verify BLOOP.apk` — подпись
  `CN=BLOOP, O=BLOOP, C=RU`.

### Подпись и сборка release

Release-сборка подписывается ключом из репозитория (пароли — для
личного проекта, при публикации в магазин смените и вынесите в секреты):

```bash
cd app
npm run apk
# или конкретно release:
cd android && JAVA_HOME=<путь к JDK 17> ./gradlew assembleRelease
# файл: app/android/app/build/outputs/apk/release/app-release.apk
```
Ключ: `app/android/app/bloop-release.keystore`, alias `bloop`,
пароли `bloop2026` (см. `app/android/app/build.gradle`, `signingConfigs`).

### Автосборка через GitHub Actions (нужно расширенное разрешение)

Готовый workflow лежит в корне: `android-workflow.yml`. Токен, которым
пушится этот репозиторий, не имеет scope `workflow`, поэтому файл нужно
активировать вручную один раз:

```bash
mkdir -p .github/workflows && cp android-workflow.yml .github/workflows/android.yml
git add .github/workflows/android.yml && git commit -m "ci: включить сборку APK" && git push
```

После этого каждый пуш в `main` собирает `BLOOP-debug.apk` (артефакт +
release `apk-latest`).

### Сборка APK на своём компьютере

Требуется JDK 17 и Android SDK (platform 34, build-tools 34):

```bash
cd app
npm install
npm run apk     # build:www -> cap sync -> gradlew assembleDebug
# готовый файл: app/android/app/build/outputs/apk/debug/app-debug.apk
```

## iPhone (iOS)

Полноценный `.ipa` подписывается только Apple Developer-аккаунтом ($99/год) —
собрать его на Linux невозможно. Готовы три пути:

**1) PWA — установить на iPhone прямо сейчас (без Apple-аккаунта):**
откройте веб-версию BLOOP в Safari → «Поделиться» → «На экран «Домой»».
BLOOP станет иконкой-приложением на весь экран (иконка, сплэш, standalone
режим уже настроены в `manifest.webmanifest`). Работает как приложение.

**2) Codemagic — облачная сборка .ipa на macOS (нужен Apple-аккаунт):**
репозиторий содержит готовый `codemagic.yaml`. Зарегистрируйтесь на
codemagic.io, подключите репозиторий, укажите Apple Developer Team —
раннер соберёт `.ipa` в облаке (workflow `bloop-ios`).

**3) Xcode — локально на Mac:**
```bash
cd app && npm install && npm run build:www && npx cap sync ios
cd ios/App && open App.xcworkspace   # затем Product -> Archive
```
Разрешения камеры/микрофона уже прописаны в `ios/App/App/Info.plist`.
iOS-проект в репозитории: `app/ios/`.

## Доставка кода входа (SMS-каналы)

Слой `src/sms.js` отправляет код **настоящей SMS на указанный номер**
через SMS-шлюз. Настоящая SMS «из воздуха» не отправляется — оператор
принимает сообщения только от шлюза, а шлюз везде платный. Провайдер
выбирается переменной `BLOOP_SMS_PROVIDER` или определяется автоматически
по заполненным переменным окружения. Все они дают **реальную SMS на
любой номер**:

| Провайдер | Переменные окружения | Где взять ключ |
| --- | --- | --- |
| **SMS.ru** | `BLOOP_SMS_PROVIDER=smsru`<br>`BLOOP_SMSRU_API_ID=…` | Регистрация на sms.ru → личный кабинет → api_id. Бесплатно — только на свой подтверждённый номер; на другие — за деньги (рубли) |
| **SMSC.ru** | `BLOOP_SMS_PROVIDER=smsc`<br>`BLOOP_SMSC_LOGIN=…`<br>`BLOOP_SMSC_PSW=…`<br>`BLOOP_SMSC_SENDER=…` (опц.) | Регистрация на smsc.ru → логин/пароль. Платно (~2–3 ₽/SMS в РФ), пополнение от 100 ₽ |
| **Twilio** | `BLOOP_TWILIO_ACCOUNT_SID=…`<br>`BLOOP_TWILIO_AUTH_TOKEN=…`<br>`BLOOP_TWILIO_FROM=+1…` | Регистрация на twilio.com → Account SID, Auth Token, купленный From-номер. Пробные ~$15: только на верифицированные номера |
| **Свой шлюз** | `BLOOP_SMS_PROVIDER=webhook`<br>`BLOOP_SMS_WEBHOOK_URL=https://…` | Любой SMS-провайдер/шлюз: на этот URL POST-ом уходит `{ "phone": "+7…", "code": "123456", "text": "BLOOP: код …" }` — свяжите с его API |

**Пример запуска с SMS.ru:**

```bash
BLOOP_SMS_PROVIDER=smsru \
BLOOP_SMSRU_API_ID=ВАШ-API-ID \
npm start
```

Дальше при входе по номеру `+79991234567` на этот номер реально уйдёт
SMS `BLOOP: код 123456. …`. В логе появится строка
`✅ SMS-код для +7999… отправлен через smsru`.

**Консоль (если шлюз не настроен):** код печатается в лог сервера —
удобно на этапе разработки; `BLOOP_SMS_DEBUG=1` дополнительно возвращает
код в API-ответе. Если шлюз задан, но доставка не удалась (ошибка
провайдера, нет баланса) — код уходит в лог как fallback, регистрация
не блокируется.

В офлайн-приложении (APK без сервера) SMS-шлюза нет физически — код
показывается сразу тостом «SMS от BLOOP».

## Запуск

Требуется Node.js 22.5+ (используется встроенный модуль `node:sqlite`).

```bash
npm install
npm start          # сервер на http://localhost:3000
```

Переменные окружения (все необязательные):

| Переменная       | По умолчанию | Что делает                         |
| ---------------- | ------------ | ---------------------------------- |
| `PORT`           | `3000`       | порт HTTP-сервера                  |
| `BLOOP_DATA_DIR` | `./data`     | папка для базы, секрета и загрузок |
| `BLOOP_SECRET`   | генерируется | секрет для подписи токенов         |

Данные хранятся в `data/bloop.db` (SQLite), загруженные медиа — в `data/uploads/`.
Видео отдаются с поддержкой HTTP Range, поэтому перемотка в плеере работает.

## Проверка (smoke-тест)

```bash
npm install        # вместе с dev-зависимостью socket.io-client
npm run smoke      # поднимает сервер на :3107 и прогоняет 63 проверки
```

Тест покрывает: регистрацию/вход, чаты, доставку по WebSocket, присутствие,
загрузку медиа (картинки/видео), создание постов и клипов, лайки, комментарии,
просмотры, профили, аватары, удаление и разграничение доступа, а также
realtime-события ленты (post:new / post:stats / comment:new), уведомления,
хэштеги с трендами, поиск, статистику профиля и нейропомощника.

## Структура

```
server.js           — Express + Socket.IO: REST API, realtime, загрузка медиа
src/db.js           — SQLite-схема и запросы: чаты, посты, лайки, комментарии
src/auth.js         — scrypt-хэши паролей, HMAC-токены сессий
src/media.js        — multer: загрузка картинок (10 МБ) и видео (300 МБ)
public/             — фронтенд (vanilla JS, без сборки)
  index.html        — оболочка соцсети: лента, клипы, видео, чаты, профиль
  style.css         — тёмная адаптивная тема
  app.js            — роутер страниц, лента, клипы (автоплей), видео, профиль, чаты
test/smoke-test.mjs — интеграционный тест API + WebSocket
```

## API (кратко)

**Мессенджер:** `POST /api/register`, `POST /api/login`, `GET /api/me`,
`GET /api/users`, `GET|POST /api/chats`, `GET|POST /api/chats/:id/messages`,
`POST /api/chats/:id/read`.

**Соцсеть:** `POST /api/upload` (multipart), `GET /api/feed?type=&tag=&before=`,
`POST /api/posts`, `GET|DELETE /api/posts/:id`, `POST /api/posts/:id/like`,
`GET|POST /api/posts/:id/comments`, `POST /api/posts/:id/view`,
`GET /api/users/:id` (со статистикой), `GET /api/users/:id/posts`,
`PATCH /api/me`, `POST /api/me/avatar` (multipart),
`GET /api/notifications`, `POST /api/notifications/read`,
`GET /api/search?q=`, `GET /api/trends`, `POST /api/assistant` (Нейро).

WebSocket (Socket.IO): `message`, `typing`, `presence`, `presence:list`,
`chat:new`, `post:new`, `post:stats`, `comment:new`, `notification`.
Авторизация сокета — токен в `handshake.auth.token`.
